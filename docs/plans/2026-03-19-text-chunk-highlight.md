# Plan: Text Chunk Highlighting in PDF Viewer

**Date**: 2026-03-19
**Status**: Planned

---

## Problem

Text chunks from docling's HybridChunker don't have `bbox` data (the chunker merges text across elements and loses per-element provenance). Only table/image/formula chunks have bbox.

Result: when user clicks a text source, the PDF viewer opens at the correct page but there's no visual indicator showing *where* on the page the chunk text came from.

## Solution

After the PDF.js text layer renders, search its `<span>` elements for text matching the chunk content and apply a highlight CSS class.

The text layer DOM looks like:

```html
<div class="textLayer">
  <span style="left:72px; top:100px;">In spintronic terahertz</span>
  <span style="left:72px; top:114px;">emitters, THz radiation is</span>
  <span style="left:72px; top:128px;">generated by ultrafast</span>
  ...
</div>
```

Each `<span>` contains a fragment of text positioned over the canvas. We search these spans for text matching the chunk content and add a highlight background.

---

## Implementation

### Changes to `PdfViewer.jsx`

Add a new function `highlightChunkText(textDiv, chunkText)` that runs after the text layer renders.

**Algorithm:**

1. Receive `chunkText` (the source's `content` prop — passed from ContentLightbox)
2. Only run on the initial page (same as bbox: `currentPage === initialPage`)
3. Normalize both the chunk text and each span's text (collapse whitespace, lowercase)
4. Build a set of target fragments from the chunk text:
   - Split at word boundaries into ~60-char fragments
   - Also include shorter fragments (30 chars) for partial matches
5. For each text layer `<span>`:
   - Check if its normalized text appears in any fragment (or vice versa)
   - If match, add CSS class `pdf-text-highlight` to the span
6. After highlighting, scroll the first highlighted span into view if needed

**Why fragment matching instead of exact match:**

The chunk text and the PDF text layer text may differ slightly:
- Whitespace/line break differences
- Hyphenation differences
- Unicode normalization differences
- The chunk may span multiple pages (only partial text on this page)

Fragment matching (same approach as the server-side `_split_into_fragments`) handles these robustly.

**New prop**: `chunkText` (string) — the chunk's text content for highlighting

```jsx
// PdfViewer receives:
<PdfViewer
  docId={source.doc_id}
  page={source.page}
  bbox={source.bbox}
  chunkText={source.content}   // NEW
  zoom={zoom}
  pan={pan}
  dragging={dragging}
  onClick={handleContentClick}
  onError={() => setPdfFailed(true)}
/>
```

**Highlight function:**

```javascript
function highlightChunkText(textDiv, chunkText) {
  if (!textDiv || !chunkText) return

  // Normalize: collapse whitespace, lowercase
  const normalize = (s) => s.replace(/\s+/g, ' ').trim().toLowerCase()

  // Build fragments (~60 chars, split at word boundaries)
  const normalized = normalize(chunkText)
  const fragments = []
  for (let i = 0; i < normalized.length; i += 40) {
    const frag = normalized.slice(i, i + 60).trim()
    if (frag.length >= 20) fragments.push(frag)
  }

  // Search spans
  const spans = textDiv.querySelectorAll('span')
  for (const span of spans) {
    const spanText = normalize(span.textContent)
    if (spanText.length < 2) continue

    const matched = fragments.some(frag =>
      frag.includes(spanText) || spanText.includes(frag)
    )
    if (matched) {
      span.classList.add('pdf-text-highlight')
    }
  }
}
```

**When to call:** After `await tl.render()` completes (text layer is populated), call `highlightChunkText(textDiv, chunkText)`.

**When bbox exists:** If the chunk already has a `bbox`, skip text highlighting — the red rectangle is a better visual indicator. Text highlighting is the fallback for chunks without bbox.

### Changes to `ContentLightbox.jsx`

Pass `source.content` as `chunkText` prop to PdfViewer:

```jsx
<PdfViewer
  docId={source.doc_id}
  page={source.page}
  bbox={source.bbox}
  chunkText={source.content}
  ...
/>
```

### CSS addition in `App.css`

```css
.pdf-viewer-canvas-container .textLayer span.pdf-text-highlight {
  background: rgba(250, 204, 21, 0.35);  /* yellow highlight */
  border-radius: 2px;
  mix-blend-mode: multiply;
}
```

The yellow background shows through the semi-transparent text layer, making highlighted text visually distinct on the rendered PDF page.

## Edge Cases

| Case | Behavior |
|------|----------|
| Chunk has bbox | Red rectangle overlay (existing). Skip text highlight. |
| Chunk has no bbox | Yellow text highlight on matching spans |
| Scanned PDF (no text layer) | No spans to highlight — page shows without highlight |
| Chunk text doesn't match any span | No highlight — user still sees the correct page |
| Chunk spans multiple pages | Highlights whatever matches on the current page |
| User navigates to different page | Highlights only on initial page (same as bbox) |
| Very short chunk text (<20 chars) | May not produce useful fragments — highlight attempt still runs |

---

## Not in scope

- Scrolling to first highlighted span (canvas is not scrollable at 1x zoom)
- Multi-page continuous highlight
- Highlighting within bbox region (combine both approaches)

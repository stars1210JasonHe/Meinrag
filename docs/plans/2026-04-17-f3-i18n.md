## Architecture

### File layout

```
frontend/src/
  i18n/
    index.js          # i18next config + init
    locales/
      en.json         # English strings (source of truth)
      <other>.json    # Translated strings
  main.jsx            # Import ./i18n before rendering app
```

### Key organization

Flat namespaces per page to avoid deep nesting. Example:

```json
{
  "common": {
    "cancel": "Cancel",
    "confirm": "Confirm",
    "delete": "Delete",
    "loading": "Loading..."
  },
  "nav": {
    "dashboard": "Dashboard",
    "chat": "Chat",
    "graph": "Graph"
  },
  "dashboard": {
    "upload": "Upload",
    "emptyState": "Upload your first document"
  },
  "chat": {
    "askPlaceholder": "Ask anything about your documents...",
    "sources": "Sources"
  },
  "sources": {
    "highConfidence": "High confidence",
    "moderateConfidence": "Moderate confidence",
    "lowConfidence": "Low confidence"
  }
}
```

No nested objects beyond one level — keeps the file readable and grep-friendly.

### Usage pattern

```jsx
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t } = useTranslation()
  return <button>{t('common.cancel')}</button>
}
```

For components with many strings, shorthand via namespace:

```jsx
const { t } = useTranslation('dashboard')
// t('upload') instead of t('dashboard.upload')
```

### Language switcher

Small dropdown in the top-right of `AppLayout.jsx` (next to UserMenu). Icon + 2-letter language code. On change:
1. Call `i18n.changeLanguage('en' | '<other>')`
2. `i18next-browser-languagedetector` persists to localStorage automatically.

## What does NOT change

- Backend responses remain in whatever the LLM produces (English prompts → English answers). Only the **UI chrome** gets translated.
- User-uploaded document content stays in its source language.
- Sources panel text from PDF content stays in source language.

### Why not backend translation?
- Scope creep: backend streams LLM output, translating mid-stream is non-trivial.
- User expectation: they asked in English, they want English back. If they want Chinese answers, they ask in Chinese (LLM handles this).

## Risks

| Risk | Mitigation |
|---|---|
| String overflow in second language (German/Chinese tend to be longer/shorter) | Test each page; fix with CSS `text-wrap` or shorter translation |
| Plurals differ by language | Use `t('items', { count: n })` — i18next handles plural rules automatically |
| Forgot to translate a string | `<Suspense>` fallback + "debug: true" in dev surfaces missing keys |
| Date/number formatting confusion | Keep scores/percentages as numbers (e.g. "53%") — no locale-sensitive formatting in this app |
